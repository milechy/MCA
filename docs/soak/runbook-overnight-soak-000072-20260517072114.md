# Runbook: Overnight Soak (000072)

Launch a long-running soak with `scripts/ralph/soak-harness.sh`, monitor it via logs and dashboard, and stop cleanly.

## 1. Pre-flight

Verify the environment before starting:

```bash
git status --porcelain                          # should be empty
cat /Users/hkobayashi/MCA/.env | grep OPENROUTER_API_KEY  # must be present
docker info                                     # daemon running (needed for supabase-local gate)
```

## 2. Start the harness

Launch in detached mode with defaults tuned for an overnight run (24h, 30 stories/hour, approval mode):

```bash
scripts/ralph/soak-harness.sh start \
  --duration-hours 24 \
  --rate-per-hour 30 \
  --mode approval
```

For fully autonomous auto-approve behavior, use `--mode fullauto`.

## 3. Confirm launch

Check that both processes are running:

```bash
scripts/ralph/soak-harness.sh status
```

Expected: `daemon: RUNNING` and `supplier: RUNNING`. If either shows `EXITED EARLY`, inspect the corresponding log under `.ralph/soak/` before proceeding.

## 4. Monitor via tail and dashboard

### Live logs
Stream combined logs in a dedicated terminal to spot crashes or rate-limit errors:

```bash
scripts/ralph/soak-harness.sh tail both
```

Or watch a single component:

```bash
scripts/ralph/soak-harness.sh tail daemon
scripts/ralph/soak-harness.sh tail supplier
```

### Dashboard check
Periodically check the high-level story board from the repo root:

```bash
node scripts/ralph/dashboard.js --markdown | head -80
```

Look for:
- Stories moving through `queued → plan → diff → commit → push → pr`
- No pile-up at `OPENCODE_RUNNING` or `DIFF_APPROVAL_PENDING`
- Escalation count staying flat

## 5. Stop cleanly

When the run is complete (or in the morning), terminate both processes:

```bash
scripts/ralph/soak-harness.sh stop
scripts/ralph/soak-harness.sh status   # confirm both stopped
```

If the daemon exited because it hit `--duration-hours`, the supplier may still be running; `stop` terminates it safely.
