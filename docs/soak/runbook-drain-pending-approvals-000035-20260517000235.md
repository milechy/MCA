# Runbook: Drain Pending Approvals After Overnight Approval-Mode Soak

**Runbook ID**: `runbook-drain-pending-approvals-000035-20260517000235`  
**Purpose**: Inspect and approve all DIFF/COMMIT/PUSH/PR approvals that were parked during an overnight approval-mode soak test.  
**Estimated Duration**: 5–15 minutes  
**Prerequisites**: Access to the Ralph approval queue; soak test has completed and no new soak jobs are queued.

---

## Step 1: List All Pending Approvals

Query the approval queue to enumerate every parked approval item.

```bash
# Identify approvals created during the soak window
ralph approvals list \
  --status pending \
  --tags soak=overnight,mode=approval \
  --created-after "$(date -d 'yesterday 00:00' -Iseconds)"
```

**Expected Output**: A table with columns: `ID`, `TYPE` (DIFF|COMMIT|PUSH|PR), `TARGET`, `REQUESTER`, `AGE`.

**Decision Gate**:
- **Zero items** → Skip to Step 5 (post-soak verification).  
- **Non-zero items** → Note the count per TYPE and continue to Step 2.

---

## Step 2: Inspect and Triage Approvals by Category

For each approval item, open its context and confirm it was generated by the soak harness and not by an unexpected process.

```bash
# Fetch full metadata for a single approval
ralph approvals inspect <APPROVAL_ID>
```

**Inspect for**:
1. **DIFF** — Validate the diff hash matches the soak artifact manifest.  
2. **COMMIT** — Verify the commit message prefix contains `[soak-approval-mode]`.  
3. **PUSH** — Confirm the target branch is the soak scratch branch (e.g., `soak/2026-05-17`).  
4. **PR** — Check that the PR title includes the soak run ID and no external reviewers were added.

**Triage actions**:
- **Valid soak artifact** → Mark for approval (Step 3).  
- **Unexpected / anomalous** → Park it in `quarantine` and open an incident ticket; do **not** bulk-approve.

---

## Step 3: Bulk-Approve Valid Soak Artifacts

Approve all items that passed inspection in Step 2.

```bash
# Approve by filtering on soak tag (acts only on items you inspected)
ralph approvals approve \
  --status pending \
  --tags soak=overnight,mode=approval \
  --require-inspected true
```

**Alternative (single-item precision)**:
```bash
ralph approvals approve <APPROVAL_ID> --reason "soak-drain-runbook-20260517000235"
```

**Expected Output**: Confirmation message listing the number of approvals granted. Each TYPE counter should match Step 1.

**Rollback**: If you accidentally approve an anomalous item, immediately run:
```bash
ralph approvals revoke <APPROVAL_ID> --reason "soak-drain-runbook-rollback"
```

---

## Step 4: Verify Queue Drainage

Confirm that no pending soak approvals remain and that downstream pipelines triggered successfully.

```bash
# Re-check pending count
ralph approvals list --status pending --tags soak=overnight,mode=approval | wc -l
```

**Expected Output**: `0`

**Pipeline spot-check** (sample one approval per TYPE):
```bash
ralph pipelines list --triggered-by <APPROVAL_ID> --status running,succeeded
```

- All sampled pipelines should be in `succeeded` or `running` state.  
- Any pipeline in `failed` should be investigated before declaring drainage complete.

---

## Step 5: Capture Post-Soak Metrics and Close Out

Record the soak results and reset the environment for the next test cycle.

```bash
# Export approval statistics
ralph approvals export-metrics \
  --tags soak=overnight,mode=approval \
  --output-format json \
  > soak-metrics-$(date -Iseconds).json
```

**Metrics to capture**:
| Metric | Value |
|--------|-------|
| Total approvals drained | `<count from Step 1>` |
| DIFF approvals | `<count>` |
| COMMIT approvals | `<count>` |
| PUSH approvals | `<count>` |
| PR approvals | `<count>` |
| Anomalies quarantined | `<count from Step 2>` |
| Drain duration | `<end time – start time>` |

**Cleanup** (optional but recommended):
```bash
# Deregister the soak scratch branch and temporary artifacts if the pipeline succeeded
ralph soak cleanup --run-id 20260517000235 --confirm-drained
```

**Sign-off**: Update the soak dashboard or ticket with the metrics JSON and mark the run as `drained`.

---

## Escalation

- If any approval cannot be inspected due to missing metadata, escalate to the **Platform Reliability** channel immediately.
- If downstream pipelines enter a `failed` state after approval, freeze further soak tests and page the **CI/CD On-call**.
