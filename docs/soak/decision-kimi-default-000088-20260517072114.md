# ADR-2026-05-14: Promote OpenCode + Kimi K2.6 to Default Execution Provider

## Status

Accepted

## Context

Ralph currently supports multiple execution providers for autonomous code changes:

- **NemoClaw** (formerly default): An internal provider based on NVIDIA NeMo + claw toolchain.
- **OpenCode + Kimi K2.6**: An alternative provider using the OpenCode platform routed through OpenRouter to the moonshotai/kimi-k2.6 model.

After an extended soak-test period, we have sufficient operational data to evaluate whether the new provider should become the default.

## Decision

Promote **OpenCode + Kimi K2.6** to the **default** execution provider for Ralph soak runs.

Demote **NemoClaw** to **opt-in** status. Users or pipelines that explicitly require NemoClaw must now request it via configuration or command-line flag.

## Consequences

### Positive

- **Improved performance**: Kimi K2.6 demonstrates consistently lower latency and higher throughput on typical code-editing tasks observed during soak tests.
- **Broader ecosystem compatibility**: OpenCode/OpenRouter integration gives Ralph access to a wider range of fallback models without provider-specific wiring.
- **Reduced maintenance**: Fewer bespoke provider-specific patches are required compared with the legacy NemoClaw stack.

### Negative / Risks

- **Model drift**: Future updates to `moonshotai/kimi-k2.6` via OpenRouter could introduce regressions; pinning and canary logic remain necessary.
- **Vendor dependency**: Increased reliance on OpenRouter uptime and API stability.
- **NemoClaw transition**: Existing pipelines hard-coded to NemoClaw may break if they do not explicitly opt in; a changelog notice and migration guide are required.

## Alternatives Considered

| Alternative | Outcome | Reason |
|---|---|---|
| Keep NemoClaw as default | Rejected | Slower iteration cycle and higher infra cost observed during soak. |
| Run both providers in 50/50 split | Rejected | Adds operational complexity; decision defers rather than resolves the default question. |
| Promote a different model (e.g., GPT-4 class) | Rejected | Kimi K2.6 outperformed alternatives in cost/quality trade-offs during evaluation window. |
