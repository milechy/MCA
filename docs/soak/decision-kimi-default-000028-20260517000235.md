# ADR-2026-05-14: Promote OpenCode + Kimi K2.6 to Default Provider, Demote NemoClaw to Opt-In

## Status
- **Decision Date:** 2026-05-14
- **Effective Date:** 2026-05-14
- **Status:** Accepted

## Context
The system previously used NemoClaw as its default execution provider. After an extended soak-test period, the OpenCode + Kimi K2.6 (via OpenRouter) stack has demonstrated superior performance, reliability, and cost-effectiveness compared to NemoClaw. This decision records the promotion of OpenCode + Kimi K2.6 to the default provider and the demotion of NemoClaw to an opt-in alternative.

## Decision
We have decided to:
1. **Promote** OpenCode + Kimi K2.6 (via OpenRouter) to the **default** execution provider.
2. **Demote** NemoClaw to an **opt-in** execution provider.

## Consequences

### Positive
- Improved execution reliability and performance for the majority of workloads.
- Reduced operational overhead by standardizing on the more stable stack.
- Clear separation of concerns: default path for general use, opt-in path for specialized or legacy NemoClaw-specific requirements.

### Negative / Risks
- Users or pipelines explicitly dependent on NemoClaw behavior must now explicitly opt in, which is a breaking change for existing configurations that relied on the implicit default.
- Monitoring must be maintained on the opt-in NemoClaw path to ensure it remains viable for users who choose it.

## Migration Notes
- Any existing configurations or scripts that do not specify a provider will now implicitly use OpenCode + Kimi K2.6.
- To continue using NemoClaw, users must explicitly set the provider to `nemoclaw` (or equivalent configuration flag) in their execution requests.
