# ADR-2026-05-14: Promote OpenCode + Kimi K2.6 to Default Provider, Demote NemoClaw to Opt-In

**Status:** Accepted on 2026-05-14; soak completed 2026-05-17.

**Related:**
- Soaking period tracking: this document (`decision-kimi-default-000108-20260517072114.md`).

## Context

We have been running A/B tests and soaking phases for execution providers in Ralph. The current landscape is:

- **NemoClaw** has been the default provider, but soak data and internal benchmarks show it lagging in reliability and throughput under sustained load.
- **OpenCode** (the interactive agent framework) paired with **Kimi K2.6** (via OpenRouter) has completed a successful soak period, demonstrating stable execution, better error recovery, and consistent token-level performance.

We need to decide which provider serves as the *default* for new and existing Ralph workloads, and which moves to *opt-in* status.

## Decision

1. **Promote** OpenCode + Kimi K2.6 (via OpenRouter) to the **default** execution provider for Ralph.
2. **Demote** NemoClaw to **opt-in** status. Users may still select NemoClaw explicitly, but it will no longer be the default.

## Consequences

### Positive
- Improved default reliability and throughput based on soak telemetry.
- Better alignment with the current agent-style execution model (OpenCode).
- Reduced surprise regressions for users who expect the default path to be the most stable.

### Negative / Risks
- Users with existing NemoClaw-specific tuning or integrations will need to explicitly opt into NemoClaw going forward.
- A brief migration window is advisable to communicate the change to active users.

## Migration Notes

- The change is effective immediately in the worktree that contains this decision.
- Downstream configuration should update the default provider knob from `NemoClaw` to `OpenCode-KimiK2-OpenRouter`.
- NemoClaw remains available as a non-default option for compatibility and specialized use cases.
