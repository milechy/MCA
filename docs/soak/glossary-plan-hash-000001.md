The `plan_hash` is a content-based identifier assigned to each execution plan to enable deterministic deduplication and caching. It is computed by first serializing the plan into a canonical JSON representation—where object keys are sorted lexicographically, arrays preserve order, and whitespace is normalized—then hashing the resulting string. A prefix of the SHA-256 digest is used as the final hash value to keep identifiers compact while maintaining a low collision probability. Because canonical JSON ignores irrelevant formatting differences, two plans that are semantically identical but generated from different pipelines or at different times will always produce the same `plan_hash`. This stability ensures that retrying, re-scheduling, or replicating a plan never creates duplicate work, and it allows distributed consumers to agree on a single identifier without central coordination. The `plan_hash` therefore acts as a durable fingerprint of the plan’s intent rather than its transient representation.
