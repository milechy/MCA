A `plan_hash` is a deterministic identifier computed from a system plan by first serializing the plan into a canonical JSON representation—where keys are sorted lexicographically, arrays preserve order, and numeric and boolean types follow strict formatting rules—and then taking the first 16 characters of the resulting SHA-256 digest. By enforcing a canonical form, the hash remains stable across any two plans that are semantically identical, even if they were originally produced by different generators or persisted with superficial formatting differences. This property allows the `plan_hash` to serve as a reliable key for deduplication, caching, and traceability throughout the pipeline. Because only a fixed prefix of the SHA-256 output is used, collisions within a single workload are statistically negligible while keeping identifiers concise and human-readable. Consumers must therefore treat any change to the canonical JSON specification as a breaking change that invalidates previously computed hashes, and should always normalize inputs before hashing.
