# Resume-After-Security-Stop Workflow

The resume-after-security-stop workflow is a **admin-only** recovery path designed to restore an agent session after a security stop has been triggered. It is **single-use**: once a stop is resumed and the session continues, the same stop token or event cannot be resumed again, ensuring each security incident is reviewed individually. The workflow **never** transitions into fullauto mode; after resuming, the agent remains under supervised or constrained execution, and full autonomy is not reinstated automatically. An administrator must explicitly acknowledge the security stop, verify the cause, and approve the resume action through a dedicated control interface before the agent proceeds. This design prevents silent or automatic bypass of safety boundaries and maintains accountability for every restart after a halt.
