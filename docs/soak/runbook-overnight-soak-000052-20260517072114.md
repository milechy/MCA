# Runbook: Overnight Saturated Soak (000052)

Use this runbook to start an overnight soak with `scripts/ralph/soak-harness.sh`, monitor progress via real-time tail and periodic dashboard snapshots, and shut down cleanly.

## 1. Pre-flight check

Before starting, verify the environment:

```bash
git status --porcelain        # should be empty
cat /Users/hkobayashi/MCA/.env | grep OPENROUTER_API_KEY   # must be present
docker info                   # daemon running (needed for supabase-local gate)
```

## 2. Start the harness

Launch the soak harness in detached mode. The defaults below are tuned for an overnight run at 30 stories/hour with auto-stop after 24 hours:

```bash
scripts/ralph/soak-harness.sh start \
  --duration-hours 24 \
  --rate-per-hour 30 \
  --mode approval
```

For a fully autonomous run (auto-approves DIFF/COMMIT/PUSH/PR), use `--mode fullauto`.

## 3. Confirm launch

Check that both processes started successfully:

```bash
scripts/ralph/soak-harness.sh status
```

You should see `daemon: RUNNING` and `supplier: RUNNING`. If either shows `EXITED EARLY`, inspect the corresponding log under `.ralph/soak/` before proceeding.

## 4. Monitor via tail

Stream the combined logs in a dedicated terminal to spot crashes or rate-limit errors in real time:

```bash
scripts/ralph/soak-harness.sh tail both
```

Or watch just one component:

```bash
scripts/ralph/soak-harness.sh tail daemon
scripts/ralph/soak-harness.sh tail supplier
```

## 5. Monitor via dashboard

Periodically check the high-level story board from the repo root:

```bash
node scripts/ralph/dashboard.js --markdown | head -80
```

Look for:
- Stories progressing through `queued → plan → diff → commit → push → pr`
- No large pile-up at `OPENCODE_RUNNING` or `DIFF_APPROVAL_PENDING`
- Escalation count staying flat

## 6. Stop cleanly

In the morning (or when the run is complete), stop both processes gracefully:

```bash
scripts/ralph/soak-harness.sh stop
scripts/ralph/soak-harness.sh status   # confirm both are stopped
```

If the daemon self-exited because it hit `--duration-hours`, the supplier may still be running; `stop` terminates it safely.
