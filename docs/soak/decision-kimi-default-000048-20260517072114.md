# ADR-2026-05-14: Promote OpenCode + Kimi K2.6 to Default, Demote NemoClaw to Opt-In

## Status

Accepted

## Context

Ralph maintains a multi-provider soak testing infrastructure for evaluating code-generation model pipelines. At the time of this decision, two primary providers were in active rotation:

- **OpenCode + Kimi K2.6 (via OpenRouter)** — newer pipeline leveraging the Kimi K2.6 model through the OpenCode execution environment and OpenRouter API aggregation.
- **NemoClaw** — incumbent pipeline that had previously served as the default provider.

Soak metrics over the preceding evaluation period indicated consistent reliability, latency, and output-quality wins for the OpenCode / Kimi K2.6 combination relative to NemoClaw. Operational readiness (error rates, token economy, and context-window handling) also met or exceeded the thresholds required for default promotion.

## Decision

1. **Promote** the OpenCode + Kimi K2.6 pipeline to the **default** provider for all standard soak workloads.
2. **Demote** NemoClaw to **opt-in** status, retaining it for:
   - Backward-compatibility verification,
   - Comparative benchmarking, and
   - Explicit user override when requested.

## Consequences

- **Positive:**
  - Improved median latency and output quality for default soak jobs.
  - Reduced operational toil by aligning the default path with the best-performing pipeline.
  - Simpler onboarding of new soak configurations (no need to explicitly select the superior provider).

- **Negative / Risk:**
  - NemoClaw drift: because it is no longer exercised by default, regressions in NemoClaw-specific integrations may go unnoticed unless opt-in jobs are periodically scheduled.
  - Dependency on OpenRouter uptime increases; mitigated by existing fallback logic.

## Related Decisions

- Previous default-provider ADRs for NemoClaw (superseded by this record).
- Future ADRs may reverse this decision if soak metrics shift materially.
