# `pre_exec_diff_hash` and `post_exec_diff_hash`

These two hashes are produced as part of a soak test’s wired-loop boundary to track whether the filesystem changed while an AI agent was executing.

- `pre_exec_diff_hash` is computed immediately **before** the agent begins its turn. It captures a hash of the `git diff` of the repository (or the requested paths) at that moment, representing the "clean" or "known" state.

- `post_exec_diff_hash` is computed immediately **after** the agent finishes its turn. It captures the `git diff` again after the agent has potentially modified files.

By comparing these two hashes, the soak harness can quickly determine whether the agent made any changes. If the hashes differ, the diff content is captured to produce the candidate patch that is ultimately reviewed. This mechanism is lightweight and ensures that only changes introduced by the agent within the loop boundary are considered, isolating agent behavior from other external filesystem mutations.
